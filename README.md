# Paper Replay Lab

**A local computational-claim and evidence-receipt companion. Maintainer: walker512.**

Turn a declared computational claim into a pinned experiment and checkable evidence receipt. Not an autonomous scientist, a scientific-truth detector, or a replacement for DVC/ReproZip.

## Try it (Python 3.10+; no runtime dependencies)

Review `examples/finite_difference/experiment.py` before execution.

```sh
python -m paper_replay validate examples/finite_difference/manifest.json
python -m paper_replay run examples/finite_difference/manifest.json --out run-001 --allow-execute
python -m paper_replay verify run-001
python -m unittest discover -s tests -v
```

The output directory must be new. It contains a manifest copy, metrics, local logs, receipt and Markdown report. Exit code 0 from `run` means all declared numerical checks passed; 2 means a negative, missing-evidence, input mismatch or execution-failure result; 1 means invalid setup. `verify` exit 0 means internally consistent, **not necessarily a successful experiment**. Read its `status` field.

## What it does

- Pins the entry script and declared inputs with SHA-256; checks before and after execution.
- Requires explicit execution opt-in and uses a fresh metrics destination, avoiding stale output.
- Distinguishes `supported`, `not_supported`, `insufficient_evidence`, `input_mismatch` and `execution_error`.
- Recomputes claim checks during offline receipt verification.
- Rejects duplicate JSON keys, NaN/Infinity, missing metrics and unpinned or option-style script entrypoints.

Claims explicitly state a metric, expected value and absolute tolerance. `supported` means **this specific artifact met its declared numeric rule**, not that a paper is correct. Users must justify tolerances; loose tolerances can make meaningless claims pass.

## Security and limitations

**Run only trusted, reviewed scripts. This tool is NOT a sandbox.** `--allow-execute` grants the Python script the current user's local privileges. Hashes establish file identity, not safety. Do not execute manifests downloaded from strangers. No network, filesystem or subprocess isolation is provided. Timeout affects the direct process; descendants may survive. Logs have no size bound. Use an independently configured disposable sandbox for external code.

Receipts are unsigned. Verification proves internal consistency only: an attacker who replaces both manifest and artifacts can create a new self-consistent bundle. Environment fields are self-reported. The tool does not recreate dependencies, validate every imported module, preserve the full environment or certify source provenance. Logs/metrics may contain secrets; inspect before sharing. No automatic upload exists.

Limits: Python entry scripts only; flat JSON metrics; absolute numeric tolerance only; no statistical uncertainty rules, container executor, fresh external-paper experiment replication or measured overall competitor advantage. The additional CMA method sample is an original synthetic trial, not paper-table replication.

## Install and test

From the extracted source folder, `python -m paper_replay ...` runs without installation. For an installed `paper-replay` command, create a virtual environment and run `python -m pip install .` there. The build uses setuptools; no runtime dependencies are required. This source distribution is not a claim of publication on PyPI.

Run `python -m unittest discover -s tests -v`. These public tests execute reviewed bundled code and synthetic temporary scripts; they are not an untrusted-code sandbox. The standard suite does not download data, call models, or run fresh CMA optimization. Windows skips two POSIX-only cases. Use a new output directory for every example; outputs are never silently overwritten.

## Verified scope and practical value

The CLI combines explicit numeric contracts, saved-source imports, artifact fingerprints, offline consistency verification and an opt-in all-claims acceptance gate. It can be used alongside an existing pipeline without adopting a full experiment platform. These are implemented conveniences, not exclusive capabilities or demonstrated human time savings.

The unchanged 0.1.2 runtime previously passed private Ubuntu/macOS/Windows × Python 3.11/3.12 CI, including the receiver gate: Linux/macOS executed 74 tests each; Windows executed 72 with two POSIX skips. The current source package is separately extracted and locally retested. No new cross-platform run, fresh optimization or independent scientific replication is implied. See [validation](docs/VALIDATION.md), [direct comparison](docs/DIRECT_COMPETITORS.md) and [utility assessment](docs/UTILITY_ASSESSMENT.md). FullFighting and DVC plus an author checker also handled the matched negative cases correctly; no overall superiority is established.


This imports actual saved DVC output without running a DVC command or experiment. The receipt explicitly states `imported` and `executed=false`. ## Receiving results in CI

Use `paper-replay verify BUNDLE --require-supported` when a downstream job must require **both** evidence integrity and all declared checks passing. Exit 0 passes that explicit gate; exit 2 means the bundle is consistent but claims are negative or incomplete, execution failed, or input fingerprints do not match the manifest; exit 1 means invalid/missing/tampered evidence. Without the flag, `verify` retains its integrity-only behavior and returns 0 for consistent negative-result bundles. Imported results remain unexecuted, regardless of gate success. No authenticity, freshness or scientific validity is implied.
